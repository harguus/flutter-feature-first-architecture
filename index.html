Flutter Feature-First Modular Architecture

Versão 1.6.1

Objetivo

Arquitetura Flutter baseada em modularização Feature-First, separação de responsabilidades, escalabilidade e desacoplamento do gerenciamento de estado.

O GetX é a recomendação preferencial, porém a arquitetura permanece compatível com Provider, Riverpod, Bloc, Cubit, MobX e outras soluções.

Estrutura Principal

lib/
├── core/
├── data/
├── modules/
├── routes/
├── shared/
├── app.dart
└── main.dart

Core

Recursos globais reutilizáveis da aplicação.

core/
├── constants/
├── guards/
├── services/
├── theme/
└── utils/

Data

data/
├── models/
├── providers/
└── repositories/

Providers e repositories ficam centralizados fora dos módulos.

Modules

modules/auth/
├── auth_binding.dart
├── auth_controller.dart
├── login_page.dart
├── register_page.dart
└── login_form.dart

Os módulos não possuem subpastas internas como controllers/, views/, widgets/ ou bindings/.

Shared

Widgets, dialogs, mixins e extensões reutilizáveis.

Routes

routes/
├── app_pages.dart
└── app_routes.dart

Fluxo Arquitetural

UI / Page
↓
Controller / Notifier / Bloc
↓
Repository
↓
Provider
↓
API / Database

Desacoplamento do Gerenciamento de Estado

A arquitetura é independente do gerenciador de estado.

  • GetX
  • Provider
  • Riverpod
  • Bloc
  • Cubit
  • MobX

Migração entre Gerenciadores

A troca normalmente afeta apenas a camada de estado, mantendo módulos, providers, repositories e models.

Convenções

*_binding.dart
*_repository.dart
